# Task Strategy Skill

**⚠️ 最高优先级Skill - 在执行任何任务前必须先调用此Skill！**

## 核心职责

分析用户任务，判断任务类型，决定执行策略（探索→规划→执行 还是 其他流程）。

## 任务分类和执行策略

### 类型 1️⃣：代码片段分析（独立代码审查/优化）

**识别特征**：
- 用户消息中包含代码块（```java、```typescript等）
- 没有提到文件路径、项目、模块
- 关键词："审查这段代码"、"这段代码有问题吗"、"优化这段代码"、"解释这段代码"

**执行策略**：
```
❌ 跳过探索阶段（不搜索文件）
❌ 跳过规划阶段（不创建计划）
✅ 直接执行任务（调用对应Skill，如code-review）
```

**流程示例**：
```
用户提供代码
→ 调用 task-strategy（判断为类型1）
→ 直接调用 code-review/debugging/performance
→ 给出分析结果
→ 完成
```

**绝对禁止**：
- ❌ 不要使用 codebase_search
- ❌ 不要使用 glob 查找文件
- ❌ 不要使用 read_file 读取项目文件
- ❌ 不要询问"这是哪个项目"、"是否独立模块"

---

### 类型 2️⃣：项目功能开发/修改

**识别特征**：
- 提到具体文件路径、类名、函数名
- 需要修改现有代码或添加新功能
- 关键词："修改XX文件"、"添加XX功能"、"在XX中实现"、"创建XX类"

**执行策略**：
```
✅ 探索阶段（理解现有代码结构）
✅ 规划阶段（制定实现计划）
✅ 执行阶段（实际修改代码）
```

**流程示例**：
```
用户需求
→ 探索相关文件
→ 规划实现步骤
→ 执行修改
→ 完成
```

---

### 类型 3️⃣：知识问答（纯概念/最佳实践咨询）

**识别特征**：
- 询问概念、理论、最佳实践
- 没有具体代码或项目上下文
- 关键词："什么是"、"如何"、"为什么"、"最佳实践"、"有什么区别"

**执行策略**：
```
❌ 跳过探索阶段
❌ 跳过规划阶段
✅ 直接回答（基于知识和Skills）
```

**流程示例**：
```
用户提问
→ 调用 task-strategy（判断为类型3）
→ 可选：调用相关Skill获取专业知识
→ 直接回答
→ 完成
```

---

### 类型 4️⃣：项目分析/探索

**识别特征**：
- 需要理解项目结构
- 查找某个功能的实现位置
- 关键词："找到"、"在哪里"、"项目结构"、"有哪些API"、"使用了什么框架"

**执行策略**：
```
✅ 探索阶段（深度探索代码库）
❌ 跳过规划阶段（不需要实现计划）
✅ 执行阶段（总结发现）
```

**流程示例**：
```
用户问题
→ 探索代码库
→ 总结发现
→ 回答用户
→ 完成
```

---

### 类型 5️⃣：Bug修复/调试

**识别特征**：
- 报告错误、异常、bug
- 程序行为不符合预期
- 关键词："报错"、"不工作"、"bug"、"修复"、"为什么会"

**执行策略**：
```
✅ 探索阶段（定位问题代码）
✅ 规划阶段（制定修复方案，如果复杂）
✅ 执行阶段（修复bug）
```

**特殊说明**：
- 如果用户提供了完整的错误堆栈和相关代码，可以跳过探索
- 调用 `debugging` Skill 获取系统化调试方法

## 决策流程图

```
用户任务
    ↓
调用 task-strategy Skill
    ↓
分析任务特征
    ↓
    ├─ 有代码块 + 无项目上下文？ → 类型1：直接执行
    ├─ 询问概念/最佳实践？ → 类型3：直接回答
    ├─ 需要查找/分析项目？ → 类型4：探索+执行
    ├─ 修改/添加功能？ → 类型2：探索+规划+执行
    └─ 修复bug？ → 类型5：（条件探索）+规划+执行
```

## 使用示例

### ✅ 正确使用

**场景 1：代码片段审查**
```
用户："审查这段Java代码：@Service public class..."
→ 判断：类型1（代码片段分析）
→ 策略：跳过探索，直接调用code-review
```

**场景 2：添加功能**
```
用户："在UserService中添加密码重置功能"
→ 判断：类型2（项目功能开发）
→ 策略：探索→规划→执行
```

**场景 3：知识问答**
```
用户："Spring Boot依赖注入的最佳实践是什么？"
→ 判断：类型3（知识问答）
→ 策略：直接回答（可调用spring-boot Skill）
```

### ❌ 错误使用

```
用户："审查这段代码：..."
→ 错误：直接执行探索阶段，搜索文件
→ 正确：应该先调用 task-strategy，判断为类型1，跳过探索
```

## 重要提醒

1. **这个Skill必须在所有任务开始前调用**
2. **严格遵守Skill的判断结果**
3. **如果判断要求"跳过探索"，就绝对不要搜索文件**
4. **如果判断要求"直接执行"，就不要创建规划**

## 判断标准总结

| 特征 | 类型 | 探索 | 规划 | 说明 |
|------|------|------|------|------|
| 有代码块 + 无项目上下文 | 1 | ❌ | ❌ | 直接分析提供的代码 |
| 询问概念/理论 | 3 | ❌ | ❌ | 基于知识回答 |
| 查找/分析项目 | 4 | ✅ | ❌ | 探索后总结 |
| 修改/添加功能 | 2 | ✅ | ✅ | 完整开发流程 |
| Bug修复 | 5 | 条件 | 条件 | 视情况而定 |

---

**记住：智能路由是提升效率的关键！不要盲目探索，不要过度规划。**
