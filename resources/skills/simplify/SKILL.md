# Simplify: 代码审查与自动修复

对所有已变更文件进行复用、质量和效率三维度审查，并直接修复发现的问题。

## 第一阶段：识别变更

运行 `git diff`（若有暂存变更则用 `git diff HEAD`）查看变更内容。若无 git 变更，则审查用户提到的或本次对话中编辑过的最近修改文件。

## 第二阶段：并行启动三个审查 Agent

使用 `task` 工具在单条消息中同时启动三个 Agent（并行执行），将完整 diff 传给每个 Agent 作为上下文。

### Agent 1：代码复用审查

对每处变更：

1. **搜索是否存在可复用的工具函数/辅助方法**，能替代新写的代码。重点查看工具目录、共享模块、变更文件附近的文件。
2. **标记所有与现有功能重复的新函数**，建议使用现有函数替代。
3. **标记所有可用现有工具简化的内联逻辑**——手写字符串处理、路径拼接、环境变量检查、自定义类型守卫等都是典型候选。

### Agent 2：代码质量审查

对同样的变更检查以下问题：

1. **冗余状态**：与现有状态重复的状态、可直接推导的缓存值、可改为直接调用的 observer/effect
2. **参数膨胀**：为函数新增参数而非泛化或重构现有参数
3. **略有差异的复制粘贴**：应统一为共享抽象的近似重复代码块
4. **抽象泄漏**：暴露内部实现细节、或破坏现有抽象边界
5. **字符串化类型**：已有常量、枚举或品牌类型的地方使用了原始字符串
6. **不必要的注释**：解释代码在"做什么"的注释（好的命名已经说明了）、描述变更过程的注释、引用 task/caller 的注释——全部删除；只保留解释"为什么"的非显然注释（隐藏约束、微妙不变量、规避措施）

### Agent 3：效率审查

对同样的变更检查以下问题：

1. **不必要的工作**：冗余计算、重复文件读取、重复 API 调用、N+1 模式
2. **遗漏的并发机会**：本可并行的独立操作被串行执行
3. **热路径膨胀**：启动流程或每次请求/渲染的热路径中新增了阻塞操作
4. **轮询循环中的无效更新**：在定时器或事件处理中无条件更新状态/Store，下游被无谓通知——添加变更检测守卫
5. **不必要的存在性检查**：操作前先检查文件/资源是否存在（TOCTOU 反模式）——直接操作并处理错误
6. **内存问题**：无界数据结构、缺失清理、事件监听器泄漏
7. **过度宽泛的操作**：只需部分内容却读取整个文件，只需一项却加载全部数据

## 第三阶段：修复问题

等待三个 Agent 全部完成。汇总其发现，逐项直接修复。若某发现是误报或修复成本过高，注明理由跳过——不要争论，直接跳过。

完成后简要总结修复了哪些问题（或确认代码已足够整洁）。
